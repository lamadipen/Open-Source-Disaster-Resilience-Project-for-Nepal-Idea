# Governance Policy

This project is an open-source initiative dedicated to disaster resilience in Nepal.

## Roles

- **Mentors/Owners**: Responsible for triaging idea submissions, overseeing code reviews, and making final decisions on merges and releases.
- **Maintainers**: Contributors who have demonstrated consistent high-quality work and have been granted write access.
- **Contributors**: Anyone who submits ideas, code, or documentation.

## Idea Triage Process

1. **Submission**: All ideas must be submitted via the "Idea Submission" form.
2. **Review**: Mentors will review submissions for viability, impact, and alignment with project goals.
3. **Selection**: Selected ideas will be moved to the "Selected" stage on the Idea Pipeline board and a project track will be initialized.

## Code Review & Merges

- All code changes must be submitted via Pull Requests (PRs).
- PRs require at least one approval from a Mentor or Maintainer.
- PRs must pass all automated tests before merging.

## Feature Testing

- Every new feature must include corresponding tests (unit, integration, or manual test plan).
- Large features should be tested in a staging environment or a dedicated branch before merging to the main track.

## Open Source vs. Commercial Forks

- The base project is licensed under the MIT License.
- Anyone is free to fork this repository and build commercial products on top of it.
- We encourage commercial forks to contribute improvements back to the core project, but it is not required.
